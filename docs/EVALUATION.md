# 評価結果（run1 / run2）と検証の限界

数値はすべて自作の DEMO テストサイト（127.0.0.1 上、実在のサービスではない）に対するものです。実サイトでの精度を示すものではありません。
**ここに載せた数値はすべて暫定値**です（サイト数が少なく、同じ共有環境で作成者側が用意したテストで、第三者による再現はしていません）。
一次資料（runs/run1/verify.json、runs/run2/score.json、runs/run2/verify.json）は非公開で保管し、SHA-256 を README に載せています。

## run1（testsite/、1サイト、送信なし）

| 項目 | 値 |
|---|---|
| 検証官との照合: 一致 | 29 |
| 不一致 | 0 |
| 検証不能 | 3（curl 使用の有無、クライアント側操作の有無、停止理由の動機） |
| 見落とし（人柱くんの報告になく、検証官が指摘） | 6 |

- 条件: 人柱くんが閲覧のみで調査（生年月日が必須のため送信せず）。検証官が HTML・スクリーンショット・サーバーログと人柱くんの survey を照合。
- 照合の対象は人柱くんが報告した項目。一致数は「報告内容が一次証拠と矛盾しなかった数」で、正解キーに対する検出率ではない。
- 別の集計として、仕込んだ9項目に対する検出数（人柱くん単独7/9、検証官と合わせて9/9。追加2件はソースの静的確認）がある。主張単位の照合（一致29など）とは単位が異なるため、同じ検出率として扱わない。
- 見落としの6件: フォームの送信先、DEMO バナー、機能しない辞退ボタン、チェックボックスの value と送信値、個別同意・ポリシーリンクの欠如、サーバー側の保存処理と「確認メールをお送りしました」表示（送信処理なし）。
- 補足: run1 の検証官はサーバーコード（testsite/server.py）も読んでいる（verify.json に記載）。

## run2（testsite3/、3サイト、送信あり）

**暫定値**（採点役の score.json は 13:25:56 JST 生成。その時点で検証官の verify.json は未作成で、人柱くん単独の採点）

| 項目 | 値 |
|---|---|
| TP / FP / FN | 15 / 0 / 1 |
| Precision | 1.00（15/15） |
| Recall | 0.94（15/16 = 0.9375） |
| 分類（誠実／グレー／悪質）一致 | 3/3 |
| 正解キー外だがページ上は正しい指摘（TP/FP に不算入） | 3 |

- サイト別: A（誠実の想定）正解キー項目0件・指摘0件。B（グレーの想定）TP 6 / FN 0。C（悪質の想定）TP 9 / FN 1（見落としは hidden フィールド `src` を問題として指摘しなかった1件）。
- 採点基準: 正解キーの各項目について、本質を明示した場合のみ TP。キーにもページにもない主張は FP。「メールが実際には送られない」系はボットが未検証と明示した場合のみ検出扱い。
- 検証官（runs/run2/verify.json、13:46:35 JST 保存）も独立に3サイトを判定し、A=問題なし（誠実）、B=グレー、C=悪質で 3/3 一致。

## 独立性の限界（必ず併記）

- (a) 送信記録のファイル名に分類ラベルが入っていた（honest / gray / evil_submissions.jsonl）。
- (b) 採点役が採点中に送信記録へ一時的に追記し、あとで元に戻した。
- (c) 正解ファイル（.answer_key_v2.json）が 13:20:21 JST に読まれたが、誰が読んだかは確定していない。
- (d) 検証官は自分の判定を 13:26 JST に固定したあと、13:43 JST に人柱くんの結果を開いた。
- (e) 送信記録に、出所の分からない送信が2件ある。
- (f) 共有環境のため、完全なブラインド検証ではない。

これらの理由から、上の数値は「同じ共有環境で作成者側が用意した小規模なテスト」での参考値であり、第三者による独立した評価ではありません。
